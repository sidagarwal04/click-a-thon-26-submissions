Scope

What the system guarantees — and what it deliberately does not.

In Scope

  • Capture active users precisely, including active-session overlap and time-window aggregations.
  • Data correctness — every number is exact and auditable, never an estimate.
  • Present session activeness per minute, hour, and day.
  • Friendly filters (platform, country, content, and more) applied on the aggregated state and pushed down to prune the data scanned.
  • Late and duplicate events handled correctly — they never contribute to incorrect aggregations.

Out of Scope

  • Concluding a session's activeness when a heartbeat is missing for a longer duration.
  • Performance benchmarking
  • Cost control
  • TTL routing for hot and cold storage

Why ClickHouse

One engine carries the entire pipeline — and it is designed to keep carrying it as the platform grows.

The Power of One Engine

ClickHouse doesn't just store the data — it ingests, enriches, and pre-computes every insight in a single system.

  • Real-time at write time — the moment an event lands it is cleaned, enriched, and folded into pre-aggregated states; data is queryable in milliseconds with zero pipeline lag.
  • Exact answers at scale — every count is deduplicated and auditable back to the raw event, so numbers are precise, never estimates.
  • Storage that shrinks itself — columnar layout, dictionary-encoded dimensions, and modern codecs compress the hot event stream to a fraction of its raw size.
  • One moving part, not five — ingest → enrich → session state → metrics → serving all live in a single database, so there is one system to operate and debug instead of a stitched-together stack.
  • The harder the problem, the more it shines — as events grow, queries still hit precomputed states, pruned partitions, and primary-index skips instead of raw rows.

Ready for Scale — Built to Grow, Not to Be Replaced

The architecture is designed for the platform's next million viewers, not just today's demo.

  • Scale = add nodes, not rewrite code — shared storage and compute let us add replicas for read fan-out without re-architecting the schema.
  • Time never becomes the bottleneck — monthly partitioning means a year-three query prunes exactly like a year-one query.
  • States stay bounded — pre-aggregated states grow with distinct sessions, not raw events, so even a 10× event surge keeps resultsets small.
  • Rollup chain prewired — minute → hour → day → month states are already merged upward; new reporting granularities are a view away, not a pipeline rebuild.
  • Absorbs product evolution — materialized views and dictionaries can be replayed in place, so new metrics and dimensions are absorbed without a rewrite.

Solid by Design — Engineered to Last

Not a demo bolted together for one afternoon — a system built with production semantics from day one.

  • Production semantics from day one — exact deduplication and canonical per-session truth are baked into the model, not bolted on for the demo.
  • Every answer is traceable — any aggregate can be audited back to the raw event it came from; the number isn't a guess, it's a provable path.
  • Domain solved head-on — the OTT model (session start/stop, idle gaps, per-minute engagement) is modeled end-to-end instead of flattened into a generic event counter.
  • One consistent truth for everyone — real-time ops, product analytics, session insights, and BI all read from the same pre-computed states, so no stakeholder ever sees a different number.
  • Cost engineered out of the design — more traffic grows the states slightly, never the scans; cost per query stays flat as the audience and the data grow.

Beyond the Hackathon — Future Scope

The foundation is done. These are the three pillars we build on it next — from the fastest way to count the crowd, to the system that runs the business on the crowd's behavior.

Pillar 1 — Real-time ML + Agentic Workflows on ClickHouse

The fastest analytical database is currently used for SQL answers. Next, it becomes the nervous system for real-time models and autonomous workflows.

  • Real-time ML models served against live state — concurrency curves, session health, and engagement feed models that detect anomalies (a spike that is actually an outage), predict churn from degraded sessions, and forecast peak load for capacity and CDN planning.
  • Agentic workflows via N8N or equivalent orchestration — N8N polls ClickHouse's latest state and acts on what it finds. A concurrency anomaly is picked up by the poll, which triggers a workflow that runs root-cause drill-downs, drafts a summary, and opens a Jira ticket with evidence attached — no human in the loop until a human is needed.
  • Why this is credible now — the serving layer is already designed for bounded, millisecond reads. ML features and agent triggers read the same tables — no new data plumbing, no batch refresh, no warehouse detour.

Pillar 2 — LibreChat: Humans as Agents, Actions into Agentic Reactions

Today LibreChat answers questions in chat. Tomorrow it turns human actions into agentic reactions — the human stays the decision-maker, but every question and decision is captured, interpreted, and acted on.

  • Go-to-Market & Sales — an account executive asks "which titles are under-monetized in a region right now?" → agent pulls concurrency + content metadata, proposes bundles, drafts the pitch — and follow-up actions (pipeline updates, CRM notes) are triggered automatically.
  • Data Analysts & Client Relationship teams — an analyst's exploration becomes a persisted agent workflow: a question answered today becomes a self-updating report tomorrow. Account health queries (buffering, drop-offs, peak concurrency) become proactive alerts that reach the team before the client does — with evidence attached.
  • Why this is credible now — LibreChat is already wired to the ClickHouse MCP server. The chat → real query path is proven; this extends it from "answer" to "answer + action," with Langfuse traceability through every step.

Pillar 3 — Data Derivative Engine & Enterprise Dashboards

Streaming data in ClickHouse is not a report — it is context that compounds. Connecting it to additional datasets turns a single metric into a portfolio of derived intelligence.

  • Derivative engines — concurrency × content metadata → engagement indices; session behavior × revenue per content → real-time monetization yield; viewing curves × marketing spend → attribution-ready demand signals. Each derivative is a new table that inherits the same incremental, pre-aggregated, cost-bounded pipeline.
  • Enterprise dashboards on ClickStack + LibreChat — observability-grade telemetry (ClickStack) plus conversational access (LibreChat) over the same data means one source of truth for ops and executives; the boardroom dashboard and the on-call console read identical numbers.
  • Context fusion — enrich streaming events with external context (catalogue metadata, pricing, promotions, weather, sporting-event schedules) as dictionary lookups, keeping the join-free, scan-minimized discipline that makes this platform cost sub-linear at scale.

Net effect

The hackathon proved ClickHouse can be one engine that answers before the question is asked. The future scope makes it one engine that acts before the problem becomes a headline — models that see anomalies coming, agents that turn a stakeholder's action into the next action, and derivative data that turns one metric into the whole business.
