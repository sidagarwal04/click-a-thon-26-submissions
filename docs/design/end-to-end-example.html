5. Story-by-story acceptance walkthrough

US-01 Foreground-only concurrency per minute

AC
Backgrounded and heartbeat-missing periods are excluded; count matches ground truth.
minute[NOW] naive (counts sessions)[BUILD] foreground (A+B group)why
10:0422both active
10:0621A backgrounded → excluded; only B counts
10:0822A foregrounded → resumes

Correctness The failure mode the whole problem exists to prevent: naive counts A's backgrounded time → overcounts. Foreground view excludes it.

US-02 Peak over a range

AC
max per-minute concurrency within the range, respecting filters.
SELECT max(concurrency) FROM ( -- window sum over range
  SELECT minute, sum(delta) OVER (PARTITION BY platform, country, content_id, video_type ORDER BY minute) AS concurrency
  FROM delta_minute WHERE minute BETWEEN '10:00' AND '10:12' );

→ Global peak = 5 (at 10:02–10:03). For content 101 / JIO / india = 2; content 202 / JIO / india = 1; content 101 / iOS / US = 1.

US-03 Average over a range

AC
avg over per-minute foreground-only counts; sanity check avg ≤ peak.

Global minutes 10:00–10:12: (4+4+5+5+4+3+3+3+4+3+2+1+0) / 13 ≈ 3.15.  avg 3.15 ≤ peak 5 ✓

Sanity If avg > peak ever appears, backgrounded time leaked into the count (US-03 anti-pattern).

US-05 Time grains (minute / hour / day)

AC
Consistent values across grains; hour = aggregation of its minutes.
Grouping key: (grain, platform, country, content_id, video_type, category) — grain = toStartOfMinute / toStartOfHour / toDate; peak = max · avg = mean of contained minutes
SELECT toStartOfHour(minute) AS h, max(concurrency) AS peak, avg(concurrency) AS avg_conc
FROM ( -- per-minute reconstruction ) GROUP BY h;

Hour 10:00 = peak 5 (max of its minutes) / avg ≈ 3.15. Day = max/mean over 1,440 minutes. Consistency check: hour value must equal re-aggregation of its 60 minutes.

US-07 Active interval when heartbeat is missing

AC
Gap beyond timeout closes the interval at last-known-active + timeout.

Session E: last heartbeat 10:05:00, then silence (no bg event, no end event). gap_timeout = 90s → active closes at 10:06:30. Minutes after that contribute 0 even though the session row is still open — the −1 at 10:06 in delta_minute does the work. Real cadence ~40s < 90s threshold, so normal playback is never wrongly closed.

US-08 Open sessions update incrementally

AC
